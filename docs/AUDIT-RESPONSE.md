## 1. Исправлено по итогам аудита (этот спринт)

### P0-1. Ratchet менял состояние до аутентификации — **ИСПРАВЛЕНО**

`PqdrRatchet::decrypt` теперь **транзакционный**: все изменения идут на staged-копии,
а в `self` попадают только после успешной проверки AEAD-тега.

```rust
pub fn decrypt(&mut self, wire: &[u8]) -> Result<Vec<u8>, String> {
    let mut staged = self.clone();
    let pt = staged.decrypt_inner(wire)?;
    *self = staged;          // коммит только после успеха
    Ok(pt)
}
```

Дополнительно:
- явная проверка replay (`ns < nr` → `Err("replay: …")`) **до** любых изменений;
- skipped-ключ больше не сгорает при неудачной расшифровке (staged-копия отбрасывается);
- `skip_message_keys` использует `saturating_add` (закрыт переполнение из P2);
- `PqdrRatchet::encrypt` тоже стал fail-closed и **не продвигает цепочку** при ошибке AEAD.

**Тесты:** `tests/p0_ratchet_atomicity.rs` — 5 тестов, точно по критериям приёмки аудита
(replay → следующее валидное сообщение расшифровывается; мусор с новым `dh_pub` → состояние
не изменилось; подделка тела skipped-сообщения → ключ остался; мусор → состояние не изменилось).

> **Проверка на старом коде:** 4 из 5 тестов **падают** на pre-fix версии `src/pqdr.rs`
> (git stash) и проходят после фикса. Дефект подтверждён, а не теоретический.

### P0-2. Сервер мог перезаписать своё хранилище — **ИСПРАВЛЕНО**

`store::load()` схлопывал «файл есть, но не читается» в `None`, и сервер стартовал с пустым
состоянием. Добавлен `store::load_checked()`:

* `Ok(None)` — файла нет (свежий стор);
* `Ok(Some(st))` — стор загружен;
* `Err(..)` — файл **есть**, но не расшифровывается/не парсится → сервер **не стартует**.

`new_state_persist()` теперь возвращает `Result` и пробрасывает ошибку в `Engine::bind_plain_store`
/ `bind_tls_store`. Ошибки `save()` больше не глотаются — они печатаются в stderr.

**Тест:** `tests/p0_store_failclosed.rs` — чужой ключ / битый файл → сервер не стартует,
файл остаётся **байт-в-байт** неизменным; отсутствующий файл → обычный свежий стор.

### P2 / письмо-аудитор §2.1 — «тихие fallback'ы в крипте» — **ИСПРАВЛЕНО**

Было: `cipher.encrypt(...).unwrap_or_else(|_| vec![0u8; 16])` — при ошибке AEAD выдавался
«шифртекст» из нулей, неотличимый от валидного. Стало:

| функция | было | стало |
|---|---|---|
| `crypto::secretbox_encrypt` | `Vec<u8>` c zero-fallback | `Result<Vec<u8>, String>` |
| `crypto::raw_secretbox_encrypt` | `Vec<u8>` c zero-fallback | `Result<Vec<u8>, String>` |
| `pq::kem_encaps` / `kem_decaps` | zero-shared-secret при ошибке | `Result<_, EncodeError>` |
| `pq::kcb_encrypt` | zero-fallback | `Result<Vec<u8>, String>` |
| `xftp::encrypt_chunks` | zero-fallback | `Result<Vec<Vec<u8>>, String>` |
| `PqdrRatchet::encrypt` | infallible | `Result<Vec<u8>, String>` |

Обновлено ~60 call-site'ов (библиотека, бинарники, тесты). Ни одного `unwrap`/`expect` в `src/`.

### P0-6. Agent: тихая потеря сообщений — **ИСПРАВЛЕНО (частично, основное)**

1. **Ответ сервера на SEND больше не игнорируется.** `send_msg`/`flush_outbox` проверяют ответ:
   `BrokerMsg::Err(...)` → `Err("SEND rejected by the server: …")`. Раньше `send_msg` возвращал
   `Ok(id)` при `ERR AUTH` / `LARGE_MSG` / `QUOTA` — сообщение просто исчезало.
2. **Блок с несколькими MSG больше не теряет хвост.** Раньше ACK отправлялся для каждого MSG,
   а возвращался только первый — остальные удалялись из очереди и выбрасывались. Теперь все
   расшифрованные MSG складываются в `pending_msgs` и отдаются по одному; добавлен
   `recv_agent_all()` для забора всего блока.

**Тесты:** `tests/p0_agent_no_loss.rs` — 4 теста на mock-транспорте:
`ERR` → ошибка; `Ok` → успех; блок из 3 MSG → 3 сообщения (и ровно 3 ACK'а); `recv_agent_all` → 3.

### P2 — переполнение `skip_message_keys` — **ИСПРАВЛЕНО** (`saturating_add`).

## 3. Уточнения к аудиту (важно для точности)

* **«X448 нет» / PQDR только на X25519.** Модуль X448 в дереве **есть** (v0.99.3, RustCrypto
  `x448`, golden-вектор сходится с OpenSSL). Но внутри `PqdrRatchet` шаги DH по-прежнему
  X25519 — это не заявлено как «интероп с официальным клиентом», и миграция рачета на
  X448/SX448 — отдельная задача (спринт «e2e»). Мы не считаем это выполненным.
* **«Проект — исследовательский прототип».** Согласен частично: протокольное ядро покрыто
  KAT/векторами и живыми логами, но публичный v1.0 без закрытия P0/P1 мы выпускать не будем —
  версия остаётся `0.x`, а README прямо называет границы.
* **Количество тестов.** В отчётах фигурируют 90 / 148 / 153 — расхождение из-за разных
  моментов съёмки и feature-конфигураций. Сейчас: **172 теста**, `clippy` без предупреждений,
  `cargo audit` — 0 уязвимостей (4 allowlisted «unmaintained» в `audit.toml`).
* **`.gitignore`/`target/`.** Замечание P3 про `target/package/sbom.cdx.json` в репозитории —
  справедливое, исправлено в этом же спринте (untracked + `/target/` в ignore).

## 4. Ближайшие шаги (последовательность)

1. **P0-3 / P0-4 / P1-5 — стор и идентичность сервера.** WAL + снапшоты, персистентные ключи,
   fail-closed (уже сделано), ключ не из env, отказ от персистентности без ключа.
2. **P0-5 — FFI.** TLS-пиннинг fail-closed, `Arc<Mutex<Agent>>`, типизированные ошибки,
   happy-path в smoke-тесте.
3. **P0-7 — интероп.** `TlsBackend` (rustls/openssl) + CI-job против официального `smp-server`
   (PING, NEW, SUB, SEND, ACK, DEL). Это же снимает вопрос о `sessionId`-binding.
4. **P1-1 / P1-2 — протокол и сервер.** Семантика `SKEY`/`KEY`/`ACK`, теги, тексты ошибок,
   таймауты, лимиты, TTL.
5. **P1-4 + X448 в ратчете — E2E-дизайн.** Либо настоящий PQDR (SX448 + AEAD-заголовок),
   либо честное переименование собственного протокола.
6. **P2 / P3 — гигиена.** Крипто-примитивы на крейтах, `clap`, MSRV-гейт, `cargo-deny`,
   `cargo machete`, единый актуальный документ вместо трёх.

После каждого спринта — тесты, отчёт и пуш в `main`; на закрытие каждого P0/P1 будет
отдельный коммит с тестом-регрессией по критериям приёмки из ваших отчётов.

**Просьба:** после закрытия пунктов 1–3 будем рады повторному аудиту именно этих мест —
с готовыми тестами-регрессиями, чтобы проверить не только код, но и сами критерии приёмки.
